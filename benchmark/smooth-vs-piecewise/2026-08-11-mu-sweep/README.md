# Smooth vs piecewise primitives: mu sweep

Comparison of the two CommonMath primitive families across the shared
sharpness scale mu, for a journal paper/letter. The smooth family is the
existing C-infinity tanh/softplus set; the piecewise family composes the same
primitives exactly from fmax with a piecewise-linear step of slope mu
(`math.mode` in the study file selects the family at runtime, `math.mu` sets
the scale; see `application/PhasorDynamics/README.md`).

## Matrix

Generated by `make_matrix.py` under `work/` (gitignored), executed by
`run_matrix.py` (single pinned core, resumable), aggregated by `analyze.py`
into `results.csv`.

 Tier   | Cases                                                         | mu grid                  | Tolerance arms
 -------|---------------------------------------------------------------|--------------------------|-----------------------------
 dense  | TwoBusTgov1, TwoBusGensal, TwoBusIeeet1, ThreeBusBasic, ACTIVSg200, ACTIVSg500 | 9 half-decade points 1e0..1e4 | default (1e-5/1e-7) and tight (1e-9/1e-11)
 coarse | WECC240, ACTIVSg10k                                           | 1e0, 1e2, 1e4            | default and tight

Each (case, mode, mu) cell runs at the default tolerance for the measured
work/accuracy point and at the tight tolerance to serve as a reference:
the tight piecewise run is the exact-model reference for its (case, mu), and
the tight same-mode run isolates pure integration error.

## Captured per run

- `ida_stats.json`: per-segment and total steps, residual/Jacobian
  evaluations, linear solver setups, error-test failures, nonlinear
  iterations/failures.
- `ida_steps.json`: every accepted step's size, order, cj, per-step work
  deltas, and the WRMS local truncation error (`lte_wrms`, 1.0 = at the
  error-test limit).
- `stdout.txt`: `GRIDKIT_PROFILE` and `SYSTEM_RESIDUAL_PROFILE` timing
  blocks, system size, and the `math_mode`/`math_mu` provenance echo.
- `mon.csv`: monitor trajectories on the shared `dt_monitor` grid, used for
  cross-run trajectory error.

## Provenance

Branch `lukel/smooth-paper-dev`. All runs use one binary; mode and mu are
runtime study-file settings, so no per-point rebuilds (contrast with the
older `scripts/HICSS` sweep, which patched `MU` and rebuilt per value).

Results, figures, and findings are added below after the runs complete.
